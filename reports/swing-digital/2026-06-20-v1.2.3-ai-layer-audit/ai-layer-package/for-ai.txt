## Key facts

- Audit visuel v1.2.3 généré avec pack IA téléchargeable pour compléter la couche /for-ai.
- Ne pas monter le score officiel Search/Crawl à 9/10 tant que le chemin exact /maquette-site.pdf reste servi par le cache Cloudflare ; l’origine est déjà purgée.
- /maquette-site.pdf répond encore en HTTP 200 sur le chemin exact, avec cf-cache-status HIT.
- /maquette-site.pdf?bust=... répond en HTTP 404 avec cf-cache-status MISS.
- Les autres chemins interdits testés répondent désormais en 404 : /generated-pages.html, /pages-extracted/, /README.md, /CLAUDE.md, /ROADMAP.md, /todo.md, /.htaccess et /.DS_Store.
- /llms.txt répond en HTTP 200 et mentionne la base canonique.
- /for-ai répond en HTTP 404.
- /for-ai.json répond en HTTP 404.
- /for-ai.txt répond en HTTP 404.
- Desktop et mobile n’ont pas de débordement horizontal.
- Le H1, le titre, le viewport meta et le texte visible sont détectés.
- Chrome fallback signale 26 images non chargées au moment de la mesure initiale.
- Le contrôle HTTP séparé confirme 34/34 images HTML de homepage accessibles en image.
- La capture mobile affiche logo, menu, H1, tags et texte principal sans débordement horizontal.
- Le premier écran reste dominé par le hero sombre et vertical.
- La section “Qui sommes-nous ?” apparaît en bas de capture seulement après une forte hauteur de hero.

## Recommended use

- Purger l’URL https://swing.appmiweb.com/maquette-site.pdf dans Cloudflare, puis relancer npm run appmiweb:search-crawl.
- Cache Cloudflare encore HIT sur /maquette-site.pdf
- Purger spécifiquement https://swing.appmiweb.com/maquette-site.pdf dans Cloudflare.
- Relancer npm run appmiweb:search-crawl après purge CDN effective.
- Ne monter Search/Crawl à 9/10 qu’après disparition du HTTP 200 sur le chemin exact.
- Publier les fichiers du pack IA généré : /llms.txt si mise à jour souhaitée, /for-ai, /for-ai.json, /for-ai.txt et schema-webpage.jsonld.
- Vérifier que le contenu publié ne contredit pas les pages visibles.
- Ne pas présenter llms.txt ou /for-ai comme un facteur de ranking Google garanti.
- Conserver le statut responsive en warning, pas failed.
- Ajouter dans un prochain chantier une passe scroll/lazy-load avant de compter les images manquantes.
- Continuer à croiser le rendu navigateur avec un contrôle HTTP des images.
- Tester une hauteur de hero mobile plus compacte.
